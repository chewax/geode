<objective>
Add the three main-process git primitives that the whole time-travel feature rides on, and expose them across the typed IPC boundary: `treeAt(oid)` (list the .md tree at a past commit), `restoreTree(oid)` (materialize a past tree into the working dir without moving HEAD), and `changedFiles(oid)` (what changed in a commit vs its first parent). Also widen `atomicWrite` to accept binary blobs.

Purpose: These are the read/restore engine of "Go Back in Time". Every renderer wave consumes them. They are the single security-sensitive surface this phase adds (fs writes/deletes driven by an oid) and MUST honor the racy-git + no-force-checkout landmines.

Output: `src/main/fs/atomic.ts` (widened), `src/main/services/git.ts` (+3 methods, +`buildTree` helper, +`rm` import, +`TreeNode` type import), `src/shared/ipc.ts` (+3 channels, +3 `GitApi` methods), `src/main/index.ts` (+3 handlers), `src/preload/index.ts` (+3 methods). After this plan `npm run typecheck` is green and the IPC surface exists, unconsumed — the app behaves exactly as before.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main (IPC) | Sandboxed renderer invokes `treeAt`/`restoreTree`/`changedFiles` with an `oid`. Only the typed preload bridge crosses; no raw ipcRenderer. |
| main → filesystem | `restoreTree` writes and deletes files inside the vault root; `treeAt`/`changedFiles` read the git object store. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Tampering | restoreTree file deletion | mitigate | Delete set derived exclusively from `workBlobs` (IGNORE-filtered: `.git`/`.geode`/`node_modules`/`.obsidian` never enter it); `.git`/`.geode` are structurally undeletable. Never enumerate via raw `readdir`. |
| T-02-02 | Tampering | restoreTree path resolution | mitigate | All filepaths originate from git trees or `workBlobs` walking inside `dir`; neither can contain `..`; `join(dir, filepath)` stays inside the vault. Writes use `atomicWrite` (temp+fsync+rename). |
| T-02-03 | Repudiation/Tampering | materialize over a dirty working tree | mitigate | This plan preserves the ability to snapshot first (the `bringBack` caller in a later plan runs a racy-safe safety `commit` before `restoreTree`); `restoreTree` itself is atomic per file and deletions are recoverable from history. |
| T-02-04 | Information Disclosure/Elevation | new IPC args (oid) | mitigate | `requireRoot()` gates every handler to the active vault (throws "No hay vault abierto"); oids are app-generated hex echoed back from `git.graph()`, not user free-text; `git.readBlob`/`walk` reject unknown oids by throwing → surfaced as a rejected IPC promise. Sandbox (contextIsolation/nodeIntegration) unchanged. |
| T-02-05 | Elevation | no HEAD/ref mutation | mitigate | `restoreTree` never calls `git.checkout()`, never moves HEAD, never writes refs/index — it only writes/deletes working-dir files, so it cannot corrupt branch state or create a detached HEAD. |
| T-02-SC | Tampering | package installs | accept | No npm/pip/cargo installs in this phase — all libraries pre-existing and pinned in package-lock.json. Legitimacy gate N/A. |
</threat_model>
