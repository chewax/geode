# Phase 2 — UI Design Contract

> Visual and interaction contract for **Go Back in Time**: the repo-level Timeline sidebar section + the whole-app read-only "you are in the past" preview. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Scope: SOFT-01..06 (soft linear restore + past preview chrome), TIME-01..06 (repo-level timeline, transport, dual markers), SIDE-03 (Timeline as a collapsible `SidebarSection` below Notes). Out of scope: named-save flow (Phase 3), auto-snapshot cadence (Phase 4), Advanced Mode / graph / branches / hashes (Phase 5). All values below **reuse the existing Geode dark-theme system** in `src/renderer/src/index.css` and stay consistent with the Phase 1 UI-SPEC. No new scale is introduced.

---

## Design System

| Property | Value |

Initializing shadcn/Tailwind would fork the visual language and violate that lock, so the initialization gate is resolved as declined by standing project decision. Registry safety gate: not applicable (no registry in this project).

## Spacing Scale

Reuses the existing compact ~2px-step sidebar scale for pixel parity with Phase 1 and the current file tree. Do NOT introduce an 8-point scale — it would visibly shift every existing row.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| micro | 2px | Gap between transport icon buttons; gap between marker chips |
| xs | 4px | Chevron→label gap; vertical list padding; chip inner gap |
| sm | 6px | Icon→text gaps in banner/entries; entry secondary-line gap |
| md | 8px | Timeline entry horizontal padding (`8px`); transport bar padding; section header padding (`0 8px`, from Phase 1) |
| lg | 10px | Banner horizontal padding; ghost placeholder padding |
| banner-h | 36px | Full-width past-mode banner height |
| header-h | 22px | Section header height + transport bar height (matches Phase 1 section header) |
| indent | 14px | Chevron/twisty column width — unchanged from FileTree |

Exceptions: values 2px, 6px, 10px, 14px, 22px, and 36px are pre-existing or density-matched tokens retained verbatim; the scale is intentionally NOT multiples of 4 (documented in Phase 1).

## Typography

Three sizes, two weights — all already present in the sidebar/graph. No new type tokens.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Section / chip / meta | 11px | 600 (label, uppercase) · 400 (meta) | 22px header / 1.4 meta | `LÍNEA DE TIEMPO` header label (uppercase, `letter-spacing: 0.5px`, `var(--muted)`); `presente`/`viendo` marker chips (11px→10px chip text, per `.chip`); entry secondary line (relative date + what-changed) at 11px `var(--muted)` |
| Body / entry / banner | 13px | 400 (entry) · 600 (banner title, active vault) | ~20px | Timeline entry primary label; transport position text; banner text "Estás viendo el pasado" at weight 600, its `{etiqueta}` at 400; ghost-tab label (italic) |
| Hint / empty | 12px | 400 | 1.4–1.5 | Timeline empty/loading/error copy (`.tree-empty` / `.plugin-empty`); ghost placeholder body |

Weights: regular 400 for entries/hints/meta; semibold 600 for the section label, marker chips, banner title, and ghost heading. No third weight. The section header stays `var(--muted)` (VSCode look), never accent — consistent with Phase 1.

## Color

Dominant surface is the editor/main area (`--bg`); the sidebar is the secondary surface (`--panel`). This phase adds **one new semantic role**: the teal `--head` (#2dd4bf) becomes the persistent **"past mode / time-travel"** color, used everywhere the app is showing a previewed past. Accent purple stays "the live present / active / selected". This split is what makes the divergence legible for TIME-06.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#16161a` (`--bg`) | Editor/main background; editor body under preview |
| Secondary (30%) | `#1c1c22` (`--panel`) | Sidebar, section headers, transport bar, banner base |
| Raised / hover (part of 30%) | `#202027` (`--panel-2`) | Entry hover/active bg, transport button hover, chip bg |
| Border | `#2a2a32` (`--border`) | Section/transport dividers, entry separators |
| Muted text | `#9a9aa6` (`--muted`) | Section label, transport idle icons, entry secondary line, "what changed", ghost placeholder |
| Text | `#e6e6ea` (`--text`) | Entry primary label, banner `{etiqueta}`, hovered icons |
| Accent — the present (10%) | `#b794f6` (`--accent`) | See "Accent reserved for" below |
| **Past mode — time travel (new role)** | `#2dd4bf` (`--head`) | See "Past-mode teal reserved for" below |
| Destructive | `#ff6b6b` | Reserved — NOT used in this phase (see note) |

**Accent (purple) reserved for — the live present, this phase:**
- The `presente` marker chip on the newest timeline entry (`.chip.current`: accent outline + accent text) — persistent.
- The active/open note row and active tab (existing behavior, unchanged) while at the present.
- No other new accent usage. Accent is deliberately NOT used for the past-mode chrome.

**Past-mode teal (`--head`) reserved for — showing a previewed past, this phase:**
- The full-width **past banner** background wash (`color-mix(in srgb, var(--head) 14%, var(--panel))`), its bottom border (`color-mix(in srgb, var(--head) 45%, var(--border))`), and its leading icon/title text.
- The **"Volver aquí"** primary button (teal fill: `background: var(--head); color: #16161a; font-weight: 600`).
- The **editor tint** during preview: a low-opacity teal veil (`color-mix(in srgb, var(--head) 7%, transparent)`) over `.epane-body` + a `2px` inset teal top accent (`box-shadow: inset 0 2px 0 color-mix(in srgb, var(--head) 55%, transparent)`), content at `opacity: 0.9`.
- The **`viendo` marker chip** on the previewed entry (reuse `.chip.head-chip`: teal fill, `#16161a` text) — persistent.
- The **viewing entry** row highlight: `border-left: 2px solid var(--head)` + `background: color-mix(in srgb, var(--head) 10%, transparent)`.
- The transport position text and the "you are in the past" accent on the ghost placeholder note.

**Destructive red note:** "Volver aquí" overwrites the working tree but is **non-destructive** (a safety snapshot is taken first; the old content lands as *pending changes* over the present, HEAD unmoved). Per CONTEXT it must NOT use alarming red or a blocking modal — confirmation is a light, non-blocking toast. The existing per-row delete red (`#ff6b6b`) is untouched.

## Copywriting Contract

All strings in Spanish; sentence case except the uppercase section label (VSCode style). No git vocabulary, no hashes (Capa-0).

| Element | Copy |
|---------|------|
| Section label | `LÍNEA DE TIEMPO` (uppercase, always) |
| Primary CTA (past mode) | `Volver aquí` — materializes the previewed moment as the current working state (icon `CornerUpLeft`) |
| Secondary action (past mode) | `Volver al presente` (icon `ChevronsRight`) |
| Banner title | `Estás viendo el pasado` (weight 600) |
| Banner full line | `Estás viendo el pasado — {etiqueta}` where `{etiqueta}` follows the entry-label fallback chain; relative date shown as a muted secondary right after (e.g. `… — «Antes de reescribir la intro» · hace 3 días`) |
| Transport — step back (older) | tooltip `Un paso atrás` (icon `ChevronLeft`) |
| Transport — step forward (newer) | tooltip `Un paso adelante` (icon `ChevronRight`) |
| Transport — jump to present | tooltip `Saltar al presente` (icon `ChevronsRight`) |
| Present marker | `presente` (accent chip, on the newest entry, persistent) |
| Viewing marker | `viendo` (teal chip, on the previewed entry, persistent) |
| Entry primary label | Fallback chain: **human name / tag → AI commit message → relative date**. NEVER a hash (TIME-03). |
| Entry secondary line | Relative date (always visible, muted) `·` what-changed. When the primary label already fell back to the relative date, show only the what-changed here to avoid duplication. |
| What changed (TIME-04) | `1 nota cambiada` / `{n} notas cambiadas` (human "nota", not "archivo"). `title` attr lists the changed note basenames. |
| Relative date format | `ahora mismo` (<1 min) · `hace {n} minuto(s)` · `hace {n} hora(s)` · `hace {n} día(s)` · `hace {n} semana(s)` … (Spanish, singular/plural aware). Absolute datetime in `title`. |
| Ghost tab label | Keeps the note's name, rendered italic + muted (`.tab.ghost`) |
| Ghost placeholder heading | `Esta nota no existía todavía` |
| Ghost placeholder body | `En el momento que estás viendo, «{nombre}» aún no había sido creada.` (icon `FileQuestion`) |
| Timeline empty heading | `Todavía no hay versiones` |
| Timeline empty body | `Guardá una versión para empezar tu línea de tiempo.` (icon `History`) |
| Timeline loading | `Cargando línea de tiempo…` |
| Timeline error | `No se pudo cargar la línea de tiempo.` |
| Toast after "Volver aquí" | `Traído al presente como cambios sin guardar.` |
| Destructive confirmation | None. "Volver aquí" is non-destructive (safety snapshot + pending changes, HEAD unmoved); confirmation is the light toast above — **no alarming modal, no red** (SOFT-06 / CONTEXT). |

Retirement note: the per-note `TimelineScrubber` modal ("Línea de tiempo — {nota}", per-note slider) is **superseded** by this repo-level Timeline. Its date/label rendering and `readNoteAt`-preview-caching pattern are generalized; the per-note modal is removed (or reduced) so there is a single, repo-level time surface.

## Interaction Contract

### Sidebar layout (top → bottom)
1. **Vault header** (`VaultHeader`, Phase 1) — pinned top.
2. **NOTAS** `SidebarSection` (`flex`, hosts `FileTree`) — dominant, fills remaining height.
3. **LÍNEA DE TIEMPO** `SidebarSection` (`id="timeline"`, not `flex`) — always available even with no note open (TIME-02); collapsible; its list scrolls internally.
4. **VaultSwitcher** — pinned bottom (unchanged, Phase 1).

### Timeline section (SIDE-03, TIME-01..06)
- **Header**: reuses the Phase-1 section header (22px, chevron twisty, `LÍNEA DE TIEMPO` uppercase muted). No header actions (transport lives in the body).
- **Transport bar** (sticky, top of the section body, `header-h` 22px, `background: var(--panel)`, bottom border): three transparent `.icon-btn` (`size={14}`, muted → text on hover): `ChevronLeft` (Un paso atrás), `ChevronRight` (Un paso adelante), `ChevronsRight` (Saltar al presente), gap 2px. A muted 11px position label on the right: `en el presente` when `previewOid === null`, else the viewing entry's relative date in teal.
  - Disabled: `Un paso atrás` at the oldest entry; `Un paso adelante` and `Saltar al presente` when already at the present (`previewOid === null`). Disabled = `opacity: 0.4; cursor: default`.
- **Entry list** (newest-first, single source `git.graph().commits`): each row (`.tl-entry`, padding 8px, `cursor: pointer`, hover `background: var(--panel-2)`):
  - **Primary line**: the fallback label (human name/tag → AI message → relative date), 13px `var(--text)`, ellipsis, `flex: 1`; right-aligned marker chip cluster.
  - **Secondary line**: relative date (muted, always) + `·` + what-changed count (`N notas cambiadas`), 11px `var(--muted)`, ellipsis; `title` lists changed note names.
  - **Markers (persistent, TIME-06)**: newest entry always shows the `presente` chip (accent, `.chip.current`); the previewed entry shows the `viendo` chip (teal, `.chip.head-chip`). Both are visible simultaneously during time travel (different rows). The previewed row also gets `border-left: 2px solid var(--head)` + teal bg tint.
  - **Click** a row → `onSelect(oid)` → sets `previewOid` (or clears it to `null` if the newest is chosen) and drives the whole-app preview.
  - **Keep active in view**: on `previewOid` change, `scrollIntoView({ block: 'nearest' })` the viewing entry (TIME-05).
- **States**: loading `Cargando línea de tiempo…` (`.plugin-empty`); empty `Todavía no hay versiones` + body (`.tree-empty`, `History` icon); error `No se pudo cargar la línea de tiempo.`

### Entering preview (SOFT-01/02, non-destructive)
- Flush in-flight edits to disk first (`flushAll`) so nothing is lost.
- Snapshot the pane/tab/open-note layout to restore on exit (SOFT-04).
- Set `previewOid`; all data sources (file tree, tab contents, editor) read **from the commit tree via read-in-commit IPC** — the working dir and HEAD stay intact (CONTEXT lock: virtual read-only preview, no disk writes during preview).
- Editor becomes `readOnly`; pane body gets the teal tint + inset accent; the full-width banner appears.

### Past-mode banner (SOFT-05)
- Full app width, `banner-h` 36px, teal wash + teal bottom border, `padding: 0 10px`, `-webkit-app-region: no-drag`.
- Left: leading `Eye` icon (teal) + `Estás viendo el pasado` (13px/600) + ` — {etiqueta}` (400 `var(--text)`) + ` · {fecha relativa}` (muted).
- Right: `Volver al presente` (ghost/secondary button, `ChevronsRight`) then `Volver aquí` (teal-filled primary, `CornerUpLeft`). Both `no-drag`.

### Ghost tabs (SOFT-03)
- If the open note did not exist at `previewOid`, keep its tab as a ghost: `.tab.ghost` (label italic, `var(--muted)`, dashed `border-style` cue), not closed.
- The pane body shows the ghost placeholder (centered, `.placeholder`-style): `FileQuestion` icon (muted), heading `Esta nota no existía todavía` (13px/600 `var(--text)`), body `En el momento que estás viendo, «{nombre}» aún no había sido creada.` (12px muted), with a small teal `viendo` cue — never editor content.

### Transport navigation (TIME-05)
- `Un paso atrás` → move to the next older commit; `Un paso adelante` → next newer; `Saltar al presente` → clear `previewOid` (exit preview). Each updates the whole-app preview and keeps the active entry in view.

### Exit to present (SOFT-04)
- Clearing `previewOid` restores live data sources, re-enables editing, removes the banner + tint, and **restores the exact snapshotted pane/tab/open-note layout** (including the note that was open before previewing).

### "Volver aquí" — bring the moment back (SOFT-06, linear)
1. If the working tree is dirty (racy-git-safe content-vs-HEAD-blob check), take a **safety snapshot** (commit without AI) so nothing is lost.
2. Materialize: write each file of the previewed tree to the working dir and delete files that didn't exist then — **HEAD is not moved, no branch, no detached-HEAD** (CONTEXT lock; generalizes `restoreVersion` to multi-file).
3. The old content is now **pending changes** over the present line; editing is re-enabled; preview exits (banner/tint removed, layout restored).
4. Confirmation is the light, non-blocking toast `Traído al presente como cambios sin guardar.` — no alarming modal, no red.

### States summary
| State | Visual |
|-------|--------|
| At present (`previewOid === null`) | No banner; editor editable; timeline shows only the accent `presente` chip on the newest entry; forward/jump transport disabled |
| Previewing a past entry | Full-width teal banner; editor `readOnly` + teal tint; timeline shows `presente` (accent, newest) AND `viendo` (teal, previewed) simultaneously; viewing row teal-highlighted and scrolled into view |
| Open note absent at preview | Its tab persists as a ghost (italic/muted); pane body shows the "no existía" placeholder |
| Timeline empty | `Todavía no hay versiones` + body, `History` icon |
| After "Volver aquí" | Preview exits; old content sits as pending changes; toast confirms; editing re-enabled |
