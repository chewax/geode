## Phase Goal

**As a** persona que toma notas (no técnica), **I want to** que la bóveda tome una instantánea de seguridad antes de acciones riesgosas (cambiar de bóveda, cerrar la app), sólo cuando algo cambió, **so that** nunca pierdo trabajo aunque cambie de bóveda o cierre sin guardar.

<objective>
Add the two remaining safety-snapshot triggers on top of Plan 01's engine: a snapshot of the OLD vault before a vault switch reassigns the root, and a snapshot on app quit via a `before-quit` handler with a re-entrancy guard. Both call the central `snapshotIfChanged(reason)` from Plan 01, so they never invoke AI, never create an empty commit, and never throw. The third SNAP-03 trigger — going back in time — is already implemented by `bringBack` (App.tsx:507-511) and is intentionally left unchanged.

Purpose: SNAP-03 ("safety snapshots before going back in time, switching vault, or quitting — only when there are changes"). This closes the phase's behavioral surface. The work is small and confined to `src/main/index.ts`; it reuses `snapshotIfChanged` verbatim (no new commit logic) and follows the researched `before-quit` async + guard pattern to avoid the infinite-loop pitfall.

Output: one added line in the `vaultSwitch` handler (safety snapshot as the FIRST statement in the try, before `vault.setRoot`), a module-level `let quitting = false`, and an `app.on('before-quit', …)` handler. `npm run typecheck` and `npm run build` stay green.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Denial of Service | `before-quit` handler re-firing `app.quit()` | mitigate | Module-level `quitting` re-entrancy guard: first pass `preventDefault` + snapshot + `app.quit()`, second pass returns early so quit proceeds. Without it the app would hang on close (Pitfall 3). |
| T-04-06 | Tampering / data loss | Snapshotting the WRONG vault on switch | mitigate | `snapshotIfChanged` reads `vault.getInfo()` and runs BEFORE `vault.setRoot`, so it commits the old (still-active) vault. Order is load-bearing and asserted in the acceptance criteria. |
| T-04-07 | Denial of Service | A failed/throwing snapshot blocking quit or vault switch | accept | `snapshotIfChanged` never throws (Plan 01 try/catch → returns null); both call sites tolerate a null result. Snapshot failure degrades to "no snapshot", never to a hang. |
| T-04-SC | Tampering | npm/pip/cargo installs | accept | Zero new dependencies (reuses `electron` `app` lifecycle + Plan 01 `snapshotIfChanged`). Package Legitimacy Gate N/A. |
