# Phase 6 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this phase (derivative, low-surface):** three small UI touch-points that reuse the existing hand-written design system — do NOT invent a new visual language.

1. **Delete-confirmation dialog** (FILE-01) — replace native `window.confirm` with a styled modal mirroring `BranchDialog`/`CommitDialog`. Also replace the `window.alert` shown on rename errors.
2. **Refresh action** (FILE-03) — a Lucide icon button in the NOTAS `SidebarSection` header, plus a non-visual auto-refresh when the window regains focus.
3. **F2 inline rename** (FILE-02) — reuses the EXISTING inline `NameInput` (`.tree-rename`); no new visuals, only a new keyboard trigger.

**Anchoring files (source of truth for the visual language):**
- `src/renderer/src/index.css` — tokens (`:root`), `.modal*`, `.tree-*`, `.icon-btn`, `.sidebar-section-actions`, `.node-del`, `.tree-rename`.
- `src/renderer/src/BranchDialog.tsx` — modal pattern to mirror for the delete dialog.
- `src/renderer/src/CommitDialog.tsx` — secondary modal-overlay reference.
- `src/renderer/src/FileTree.tsx` — tree rows, `NameInput` inline edit, `onKeyDown`.
- `src/renderer/src/SidebarSection.tsx` — NOTAS header + `actions` slot for the refresh button.

## Spacing Scale

The codebase uses a compact, dense scale (VSCode-like). Reuse the exact paddings/gaps already present in the anchored classes — do NOT re-space existing components. New elements (refresh button, delete dialog) inherit these values.

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Row padding, small gaps |
| sm | 8px | Modal heading gap (`.modal h2` gap:8), `.modal-actions` gap:8 |
| md | 12px | `.modal-sub` bottom margin, input padding (10–12px) |
| lg | 18px | `.modal-actions` top margin |
| xl | 24px | `.modal` horizontal padding (22px vertical / 24px horizontal) |

Exceptions (intentional existing conventions — must be matched, not "corrected"): 6px flex gaps on buttons/headers, 5px `.icon-btn` padding, 22px modal vertical padding, 2px `.node-del` padding. These are the established rhythm of the app; new elements copy them verbatim rather than snapping to a strict 8-point grid.

## Typography

Effective scale for the surfaces this phase touches (declared from existing rules; do not introduce new sizes):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Modal heading (`.modal h2`) | 18px | 600 | ~1.2 (default) |
| Body / dialog text / tree label / rename input | 13px | 400 | ~1.4 (default) |

## Color

Dark theme only (`color-scheme: dark`). Tokens are CSS custom properties in `:root`. Use tokens, never raw hex, except the destructive/semantic reds already hard-coded in the app.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg` `#16161a` | App/editor background; modal overlay is `rgba(0,0,0,0.55)` over it; rename input background |
| Secondary (30%) | `--panel` `#1c1c22` / `--panel-2` `#202027` | Modal surface (`--panel`); inputs, selected tree row, buttons (`--panel-2`) |
| Accent (10%) | `--accent` `#b794f6` | See reserved list below |
| Destructive | `#ff6b6b` | Delete-confirm primary button + warning icon; matches existing red usage (`.node-del:hover`, `.modal-error`) |

Accent (`#b794f6`) reserved for, in this phase ONLY:
- Focus/selection outline of tree rows (`box-shadow: inset 0 0 0 1px var(--accent)`) — existing.
- Border of the active inline rename input (`.tree-rename` border) — existing.
- Focus border of the delete-dialog's non-destructive controls / input focus (`--accent`) — inherited from `.text-input:focus`.
- The refresh icon button hover/active tint (matches `.sidebar-section-actions .icon-btn:hover`).

Accent is NOT used for the destructive confirm button — that button is red (`#ff6b6b`) to signal the disk-touching action. Supporting muted text uses `--muted` `#9a9aa6`.

## Copywriting Contract

All strings in Spanish. Titles: capital only at start. Buttons: verb+noun. Central value must read through the copy: the delete is recoverable from history, and no irreversible disk deletion happens without an explicit, unambiguous notice.

| Element | Copy |
|---------|------|
| Primary CTA (delete dialog, destructive) | `Eliminar` |
| Secondary CTA (delete dialog) | `Cancelar` |
| Delete dialog title (nota) | `¿Eliminar la nota "{nombre}"?` |
| Delete dialog title (carpeta) | `¿Eliminar la carpeta "{nombre}"?` |
| Delete dialog body (reassurance) | `Se elimina del disco, pero podés recuperarla desde una versión anterior en el historial.` |
| Delete dialog body (carpeta, extra) | `Se eliminarán también las notas que contiene.` (only when node is a folder) |
| Rename error (was `window.alert`) | Reuse existing validation messages, rendered inline in Spanish (e.g. `Ya existe "{nombre}"`, `El nombre no puede estar vacío`, `El nombre contiene caracteres no válidos`). Shown via `.modal-error` styling or an inline error line under the input — never a native `alert`. |
| Refresh button `title`/`aria-label` | `Actualizar notas` |
| Empty state (existing, unchanged) | `.tree-empty` / `.tree-empty-title` already handle the no-notes state; this phase does not add an empty state. |

Destructive actions in this phase: **borrar nota/carpeta** (FILE-01) — always behind the styled confirmation dialog above; there is no other destructive action.

## Component Contract (this phase)

### 1. Delete-confirmation dialog (new component, e.g. `ConfirmDeleteDialog.tsx`)
- Structure mirrors `BranchDialog`: `.modal-overlay` (click-outside closes) → `.modal` (`stopPropagation`) → `<h2>` with a Lucide icon + title → `.modal-sub` body → `.modal-actions` with `Cancelar` then destructive `Eliminar`.
- Icon: `Trash2` or `AlertTriangle` (Lucide, `size={18}` to match `.modal h2`).
- Destructive button: red treatment (`#ff6b6b`); either a new `.danger` button variant (background/border `#ff6b6b` on `#16161a` text, mirroring `button.primary` geometry: `padding:10px 18px; font-weight:600`) or a red-text emphasis — executor's discretion, but it MUST read as destructive, not as the accent purple.
- Keyboard: `Enter` confirms, `Escape` cancels (same handler shape as `BranchDialog`). `autoFocus` on the confirm or cancel per existing dialog convention.
- Replaces the `window.confirm` in `App.tsx` `deleteNode(node)` (~495).

### 2. Refresh button (in NOTAS header)
- Rendered into `SidebarSection` `actions` slot (id NOTAS/EXPLORADOR header). Reveals on header hover exactly like existing actions (`.sidebar-section-actions` visibility rules).
- `<button className="icon-btn">` with Lucide `RefreshCw` `size={14–16}` (match sibling header actions). `title`/`aria-label`: `Actualizar notas`.
- Hover tint matches `.sidebar-section-actions .icon-btn:hover`.
- Optional spin feedback while refreshing: reuse the existing `.spin` keyframe class on the icon.
- Non-visual: `window` `focus` listener in an `App.tsx` `useEffect` (with cleanup) also calls `refreshTree()`. Must NOT clobber unsaved in-progress edits (respect journal/pending).

### 3. F2 inline rename (no new visuals)
- Reuses existing inline `NameInput` (`.tree-rename`) — accent border, 13px, `--bg` background. This IS the contract; no new chrome.
- New behavior only: `FileTree` `onKeyDown` gains an `F2` branch → `onStartRename(node)` → `App` sets `editingPath = node.path`. Enter confirms, Escape cancels, blur confirms (already implemented in `NameInput`).
- Validation and tab/selection remapping already handled by `renameNode` — preserve; on failure show the inline error (per copywriting table), not a native alert.
