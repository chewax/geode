<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| renderer → main | App invokes `git.treeAt`/`git.changes`/`git.commit`/`git.restoreTree`/`git.graph` via the typed preload bridge. |
| preview → working dir | Only `bringBack` writes; preview is read-only. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03 | Tampering/Repudiation | bringBack overwriting a dirty tree | mitigate | `flushAll` then a racy-safe `git.changes()` check; when dirty, a safety `git.commit()` with an explicit (non-AI) message runs BEFORE `restoreTree`, so nothing is lost; the old content lands as recoverable pending changes. |
| T-02-05 | Elevation | bringBack must not move HEAD | mitigate | `bringBack` calls `git.restoreTree` (working-dir only) and never `git.checkout`/`goToVersion`; the safety `commit` is a normal forward commit on the current branch (expected), not a checkout/detach. |
| T-02-04 | Tampering | disk writes during preview | mitigate | Preview reroutes to `git.treeAt`/`readNoteAt` only; the editor is read-only and `EditorPane.flush()` is guarded (plan 03); no write path is reachable until `bringBack`. |
| T-02-10 | Denial of Service | previewOid persisting across reload | mitigate | `previewOid` is React state only (transient) — the app always opens in the live present; never written to localStorage/settings. |
| T-02-SC | Tampering | package installs | accept | No installs this plan; all imports pre-existing and pinned. Legitimacy gate N/A. |
</threat_model>
