## Phase Goal

**As a** persona que toma notas (no técnica), **I want to** ponerle un nombre opcional a este momento y que la IA escriba la descripción de lo que cambió, **so that** guardo una versión sin ver jerga de git ni una lista de archivos.

<objective>
End-to-end human verification of the reframed save flow against the three requirements plus the two correctness fixes (AI diff scope + first-line label). No code changes: this plan runs the app and confirms the observable behavior, mirroring the Phase 1–2 UAT checkpoint style (there is no automated test harness in this repo by design).

Purpose: The phase goal ("saving is naming a point in time; AI writes the description") is only truly satisfied when a human sees the reframed dialog behave correctly with AI on and off, confirms the bug fix (AI describes only notes), and confirms the timeline shows only the title. This is the phase gate.

Output: a signed-off UAT with any issues logged. If issues are found, they are captured for a gap-closure plan; if clean, Phase 03 is complete.
</objective>

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: UAT — SAVE-01/02/03 + bug fix + first-line label</name>
  <what-built>
    The "Guardar versión" dialog reframed to name-a-moment: optional autofocused Nombre (title) + AI-written editable Descripción (body), a human "N notas cambiadas" summary (no file list), no ledger warning, and a Lucide error icon. Backend: a new `geode:ai-suggest-version` round-trip returning `{ title, description }`, the AI diff scoped to `.md` notes, and the timeline label trimmed to the first line.
  </what-built>
  <how-to-verify>
    Run the app (`env -u ELECTRON_RUN_AS_NODE npm run dev`) and open a vault with at least one note.

    1. SAVE-01 (optional name → label): edit a note, trigger Guardar versión. Confirm the Nombre field is on top and focused. Type a name (e.g. "Primer borrador"), leave/edit the description, save. In the Timeline (sidebar), confirm the entry's label is exactly "Primer borrador" (the title, not the body).
    2. SAVE-01 (empty name fallback): edit the note again, save WITHOUT typing a name and with an empty description (turn AI off first if needed). Confirm the save succeeds and the timeline entry shows a relative date (e.g. "ahora mismo" / "hace N minutos"), never a hash.
    3. SAVE-02 (AI on): with AI enabled (key + model in Ajustes), open the dialog — confirm both Nombre and Descripción auto-populate, both are editable, and "regenerar con IA" re-runs and overwrites both. While generating, the Guardar button is disabled.
    4. SAVE-02 (AI off): disable AI, open the dialog — both fields empty, Guardar is enabled immediately, and saving works.
    5. SAVE-03 (no git jargon): inspect the dialog — title reads "Guardar versión", sub-copy "Ponle un nombre a este momento.", the changed summary reads "N notas cambiadas" (no file paths, no scrollable list), there is NO "versión permanente"/"ledger" warning, and any error shows a Lucide triangle icon (no ⚠ glyph).
    6. Bug fix (AI diff scope): change a `.md` note AND a non-`.md` file (e.g. add/modify an image or a `.txt`) in the vault, open the dialog with AI on. Confirm the generated description references ONLY the note content, not the attachment. Then save and confirm the version still includes the attachment (the commit versioned it) — the summary/count reflects notes but the attachment is not lost.
    7. First-line label: save a version whose description spans multiple lines; confirm the Timeline entry shows only the first line (title), not the multi-line body.
  </how-to-verify>
  <resume-signal>Type "approved" if all seven checks pass, or describe the issues found (which check, expected vs actual).</resume-signal>
