>
> **Locked visual language:** brownfield Electron + React app. NO design-system library. Hand-written CSS in `src/renderer/src/index.css`, kebab-case classes, CSS custom-property tokens (`:root`), Lucide icons only (monochrome `currentColor`, never emojis/glyphs), Spanish strings + comments. This phase REUSES existing patterns and adds no new visual language. Every token below is an existing token in the codebase.

## Copywriting Contract

All Spanish. Titles capitalize first word only. Buttons are verb+noun.

| Element | Copy |
|---------|------|
| Primary CTA (FILE-05, safe) | `Quitar de la lista` |
| Destructive CTA (FILE-05, disk) | `Quitar y enviar a la papelera` |
| Per-vault row action tooltip | `Quitar bóveda…` |
| Remove-vault dialog heading | `¿Quitar la bóveda "{nombre}" de la lista?` |
| Remove-vault dialog body (safe reassurance) | `Se saca del selector de bóvedas. Tus archivos y todo el historial quedan intactos en el disco.` |
| Disk-delete opt-in (checkbox label) | `Eliminar también los archivos del disco` |
| Disk-delete opt-in hint | `Se mueven a la papelera del sistema (recuperable). Se borra la carpeta completa, incluido el historial de versiones.` |
| Cancel | `Cancelar` |
| Empty state (removed last / active vault) | Reuse existing `.welcome` "sin bóveda" screen; do not redefine here. If vaults remain, switch to the most recent (Claude's discretion per CONTEXT). |
| Error — unlist failed | `No se pudo quitar la bóveda: {motivo}.` |
| Error — trash failed | `No se pudo enviar la carpeta a la papelera: {motivo}. La bóveda sigue en la lista.` |
| Preview-tab affordance | No text label; the visual signal is italic. Tab tooltip stays the full path (existing `title={path}`). |

**Destructive confirmation approach (FILE-05):** single confirm dialog mirroring `ConfirmDeleteDialog`. A checkbox (default OFF) opts into disk deletion; the primary button's label and style escalate with the checkbox:

- Checkbox OFF → button reads `Quitar de la lista`, neutral/default button style (NOT red).
- Checkbox ON → button reads `Quitar y enviar a la papelera`, `button.danger` (red `#ff6b6b`).

This keeps disk deletion behind explicit intent (CONTEXT: "el borrado de disco requiera intención explícita") while presenting one action button, avoiding two adjacent destructive buttons.

## Interaction & Component Contracts

### FILE-04 — Preview tab (VSCode-style)

**Model (paneTree.ts):** add `preview: string | null` to `LeafPane` (the path currently shown as preview, or `null`). Exactly ONE preview tab per pane. Keep leaf `id`s stable (React remount invariant). Update pure ops to preserve/clear `preview`: `openInLeaf`, `dropTab`, `removePathEverywhere`, `keepOnly`, `reorderTab`, `splitWithTab`/`splitLeaf`, `makeLeaf`.

**Visual signal:** `font-style: italic` on the preview tab's `.tab-label` (add a `.tab.preview` class in `EditorPane`'s tab render). No new color, no icon, no badge. The active-tab styling (`--bg` fill, `--accent` border) is unchanged and composes with italic when the preview tab is also active.

**Interaction contract:**

| Trigger | Result |
|---------|--------|
| Single click on a note in `FileTree` | Open it in THE pane's preview tab (italic). If a preview tab already exists, REUSE it — replace its content/path in place, do not add a tab. If the note is already open as a permanent tab, just activate it (no preview created). |
| Single click on another note while a preview is open | The same preview tab is reused (path swapped); tab count does not grow. |
| Double click on a note in `FileTree` | Open/activate as a PERMANENT tab (not italic). |
| Any edit to the preview note's content | Pin: `preview → null` for that path; italic removed. (Hook at the existing edit path — `onNoteChange` / `handleChange` in `EditorPane`.) |
| Double click on the preview TAB itself | Pin (italic removed). Extra VSCode-style shortcut. |

**Where it renders:** `EditorPane.tsx` tab strip (`.tab` elements, line ~243). Single/double-click distinction lives in `FileTree` `onOpen` and is threaded through `App.tsx` handlers (`onNoteOpen` / `onSelectTab` / `onPaneNoteChange`). No change to drag-and-drop, close (X / middle-click), or split behaviors.

**Non-goals (deferred):** no pin icon/toggle button, no "keep open" affordance, no preview for split creation, no multi-preview.

### FILE-05 — Vault removal

**Per-vault row action (`VaultSwitcher.tsx`):** each known-vault `li` in `.vault-menu` gains a hover-revealed trash action, mirroring the sidebar section-actions hover pattern.

- Icon: `Trash2` `size={14}`, `--muted` at rest, `--text`/`--accent` on hover (reuse `.icon-btn` conventions). Hidden until row hover/focus; always focusable for keyboard.
- Placement: trailing edge of the row, after `.vault-menu-name`; must not collide with the current-vault `Check`. Clicking it opens the dialog and does NOT switch vaults (`stopPropagation` on the row's switch handler).
- Tooltip: `Quitar bóveda…`.

**Confirm dialog (`ConfirmRemoveVaultDialog`, new — mirror `ConfirmDeleteDialog.tsx`):**

- Structure: `.modal-overlay` → `.modal` → `h2` (with heading icon) → `.modal-sub` body → checkbox row → `.modal-actions`.
- Heading icon: `FolderX` `size={18}` (differentiates vault removal from note deletion, which uses `Trash2`).
- Body: safe-reassurance copy (see copywriting).
- Checkbox: default OFF, label + hint per copywriting; the disk-delete path routes through Electron `shell.trashItem` (recoverable), never a permanent `rm`.
- Actions (`.modal-actions`, right-aligned): `Cancelar` with `autoFocus` + the escalating confirm button.

**Keyboard safety (LOCKED — Phase 6 CR-01 lesson):** `Escape` cancels. `Enter` must NEVER trigger disk deletion. Default focus stays on `Cancelar` (`autoFocus`) even when the checkbox is ON, so a reflex Enter cancels. Disk deletion requires an explicit click on the danger button, or Tab-to-button + activate. Do not add an `onKeyDown` Enter→confirm handler.

**Active-vault edge (Claude's discretion, CONTEXT):** removing the currently-open vault switches to the most-recent remaining vault; if none remain, show the existing `.welcome` "sin bóveda" state.
