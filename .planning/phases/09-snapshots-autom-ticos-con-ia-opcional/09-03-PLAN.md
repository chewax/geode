<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 1: UAT — SC-1..SC-4 de snapshots con IA opcional</name>
  <what-built>
    Backend (09-01): flag `snapshots.aiTitles` (default OFF), IPC/preload, y `snapshotIfChanged(reason, allowAi)`
    con path de IA en cadencia (timeout ~10s + fallback al marcador) y guardrail sin IA en ciclo de vida.
    UI (09-02): toggle "Nombrar las snapshots automáticas con IA" en Ajustes → Guardado automático.
  </what-built>
  <how-to-verify>
    Preparación: relanzar la app con `env -u ELECTRON_RUN_AS_NODE npm run dev` (los cambios de main
    NO se hot-reloadean). Tener una bóveda abierta. Para las pruebas con IA, tener API key + modelo
    de IA configurados en Ajustes → IA. Para acelerar la cadencia, poné "Cada 5 minutos" en Ajustes
    → Guardado automático (o esperá el tick de 10 min).

    SC-1 (opción existe, default OFF):
    1. Abrí Ajustes → Guardado automático. Verificá que el toggle "Nombrar … con IA" existe y está
       APAGADO por defecto (primera vez / settings sin el flag). El copy debe mencionar el costo
       (usa la API key de IA) y que solo corre cuando hay cambios.

    SC-2 (OFF ⇒ marcador v1.0 intacto):
    2. Con el toggle APAGADO, editá una nota y guardala en disco. Esperá el tick de cadencia (o forzalo
       con la cadencia de 5 min). En la timeline/grafo, la nueva snapshot debe tener el marcador
       "Instantánea automática — <fecha>", idéntico a v1.0.
    3. (Guardrail de ciclo de vida) Con el toggle APAGADO, editá y cerrá la app: al reabrir, la
       snapshot de cierre también es el marcador y la app cerró sin demora perceptible.

    SC-3 (ON ⇒ IA solo con cambios reales, nunca por tiempo):
    4. Activá el toggle. Sin editar nada (vault limpio), esperá uno o dos ticks de cadencia: NO debe
       aparecer ninguna snapshot nueva (árbol limpio = no-op, no se invoca IA → no hay costo por tiempo).
    5. Editá una nota, guardala, y esperá el tick de cadencia: debe aparecer UNA snapshot nueva con
       título/descripción generados por IA (no el marcador).
    6. (Guardrail) Con el toggle ON, editá y cerrá la app: la snapshot de cierre sigue siendo el
       MARCADOR (sin IA) y el cierre no se demora — la IA solo aplica al path de cadencia.

    SC-4 (legible como guardado manual con IA):
    7. Abrí la snapshot con IA del paso 5 en la timeline: título en la primera línea y descripción en
       el cuerpo, con el mismo formato que un "Guardar versión" manual con IA.

    Fallback (invariante de no-pérdida):
    8. Con el toggle ON pero SIN modelo de IA configurado (o con una key inválida), editá, guardá y
       esperá el tick: debe crearse igual la snapshot, cayendo al MARCADOR (nunca se pierde el guardado,
       la app no muestra error bloqueante).
  </how-to-verify>
  <acceptance_criteria>
    - SC-1: el toggle existe en Ajustes → Guardado automático y está APAGADO por defecto, con copy de costo/condición.
    - SC-2: con el toggle OFF, las auto-snapshots (cadencia y ciclo de vida) usan el marcador v1.0 exacto.
    - SC-3: con el toggle ON, no se crea snapshot ni se invoca IA con el vault limpio; con cambios reales sí se crea una snapshot nombrada por IA en el path de cadencia; los paths de ciclo de vida siguen sin IA.
    - SC-4: la snapshot con IA se lee en la timeline igual que un guardado manual con IA (título + descripción).
    - Fallback: con el toggle ON pero IA no configurada/fallida, la snapshot se crea igual con el marcador (nada se pierde, sin error bloqueante).
  </acceptance_criteria>
  <resume-signal>Escribí "aprobado" si SC-1..SC-4 + fallback se cumplen, o describí los defectos observados (para gap-closure).</resume-signal>
