<objective>
Construir el puente async del `PluginContext` para plugins externos: un `MessageChannel` real cuyo lado-plugin recibe un proxy async (API v2) y cuyo lado-host traduce cada mensaje RPC a las llamadas reales del `PluginHost`/`window.geode`. Se bifurca solo el camino de activación de externos; los built-ins siguen intactos sobre la API v1 síncrona.

Purpose: Des-riesga el salto a API async separándolo del sandbox — en la Fase 11 el transporte (MessagePort + RPC) se ejercita in-window; la Fase 12 solo moverá un endpoint del port al iframe sin cambiar la API del plugin.
Output: `plugins/bridge.ts` (bridge host-side + proxy lado-plugin + `activateExternalViaBridge`), tipos del envelope RPC y `AsyncPluginContext` en `types.ts`, y el wiring del camino de externos en `App.tsx`/`index.ts`.
</objective>

  <action>
    Crear `src/renderer/src/plugins/bridge.ts` con tres piezas y exportar `activateExternalViaBridge(host: PluginHost, plugins: GeodePlugin[]): Disposable`:

    1. Host-side handler (`attachHostBridge(host, port: MessagePort): Disposable`): escucha `port.onmessage`; ante `{type:'call',id,method,args}` despacha por `method` (string dotted) a la implementación real y responde `{type:'result',id,result}` o `{type:'error',id,message}` en el catch. Métodos soportados: `activeNote` → host.activeNote(); `vault.readNote`/`vault.tree` → window.geode.vault.*; `git.graph` → window.geode.git.graph(); `editor.insertAtCursor`/`editor.getSelection`/`editor.revealRange` → host.editorInsertAtCursor/getSelection/revealRange; `runCommand` → host.runCommand(id); `notify` → host.notify(msg); `events.on` (args `[eventName, sub]`) → host.on(eventName, payload ⇒ port.postMessage({type:'event',name:eventName,payload,sub})), guardando el Disposable indexado por `sub`; `events.off` (args `[sub]`) → dispose de esa suscripción; `commands.register` (args `[serializableCmd]`, con `{id,title,category,shortcut}`) → host.registerCommand({...serializableCmd, run: () => port.postMessage({type:'invoke',commandId:serializableCmd.id})}), guardando el Disposable por commandId; `commands.dispose` (args `[commandId]`) → dispose. Un `method` desconocido responde `{type:'error',...}` con mensaje en español. El Disposable devuelto limpia el listener y todas las suscripciones/comandos registrados.

    2. Proxy lado-plugin (`buildAsyncContext(port: MessagePort): AsyncPluginContext`): mantiene un contador de ids y un `Map<number, {resolve,reject}>` de calls pendientes; un helper `call(method, ...args): Promise<unknown>` incrementa el id, guarda la promesa y hace `port.postMessage({type:'call',id,method,args})`. `port.onmessage`: ante `{type:'result',id}` resuelve y borra del map (id desconocido/huérfano ⇒ se descarta sin throw); ante `{type:'error',id}` rechaza con Error(message); ante `{type:'event',name,payload,sub}` despacha al handler local guardado por `sub`; ante `{type:'invoke',commandId}` corre el `run()` del comando local guardado por id. Expone `activeNote/vault/git/editor/runCommand/notify` que delegan en `call(...)`; `events.on` genera un `sub` incremental, guarda el handler local, hace fire-and-forget `call('events.on', eventName, sub)` y devuelve un Disposable que borra el handler local + fire-and-forget `call('events.off', sub)`; `commands.register` guarda el `cmd` local por id, hace fire-and-forget `call('commands.register', {id,title,category,shortcut})` (descarta run/isEnabled) y devuelve Disposable que hace `call('commands.dispose', id)`; `panels/statusBar/editorExtensions` lanzan Error en español "no soportado en Fase 11 (Fase 12)".

    3. `activateExternalViaBridge(host, plugins)`: por cada plugin arma `const ch = new MessageChannel()`, `attachHostBridge(host, ch.port2)`, `const ctx = buildAsyncContext(ch.port1)`, arranca ambos ports (`ch.port1.start()`/`ch.port2.start()` si aplica), invoca `plugin.activate(ctx as unknown as PluginContext)` dentro de try/catch (un plugin que falla no tumba a los demás, se loguea `[plugins]`), y acumula los Disposables (handler host-side + cleanup del activate). Devuelve un Disposable que los libera todos.

    NO tocar host.ts, react.tsx ni el path de built-ins. `unsafe-eval` y la evaluación in-window de externos siguen intactos (Fase 12).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| código de plugin externo (no confiable) → puente (host-side handler) | El plugin se evalúa in-window (unsafe-eval sigue hasta Fase 12); el puente es el único canal por el que sus llamadas llegan al host. En Fase 11 NO hay aislamiento real todavía — el aislamiento del iframe es Fase 12 (ISO-01). |
| plugin ↔ host vía MessagePort | Todo mensaje es dato serializable via structured-clone; Components/Extensions no serializables quedan fuera (panels/status/editorExt diferidos a Fase 12). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-03 | DoS | Mensaje RPC con id desconocido/huérfano | mitigate | El proxy descarta results/errors sin call pendiente sin throw; el handler responde error a methods desconocidos. Ningún camino queda colgado. |
| T-11-04 | Spoofing/Injection | `method` arbitrario desde el plugin | mitigate | El handler host-side despacha por allowlist explícita de methods; un method fuera de la lista devuelve error, no ejecuta nada. |
| T-11-05 | Elevation | Plugin accede a globals/window.geode directamente | accept | Aceptado en Fase 11 (aún in-window, unsafe-eval presente); el aislamiento real (iframe sandbox sin allow-same-origin) es Fase 12/ISO-01. Documentado en threat model de docs/PLUGINS.md. |
| T-11-06 | Tampering | Payload no serializable en commands.register/events | mitigate | El proxy manda solo el subset serializable {id,title,category,shortcut}; run/isEnabled se descartan en el borde. |
| T-11-SC | Tampering | Instalación de paquetes | accept | Este plan no agrega dependencias (MessageChannel es API nativa del navegador). Sin superficie de instalación. |
</threat_model>
