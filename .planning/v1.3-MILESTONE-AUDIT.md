## Cross-Phase Integration (6/6 WIRED)

1. **F11 `createLocalVault` → F12 + F13 fan-out** — único punto de disparo tras crear el primer cuaderno; marca backup onboarding 'invitado' (tarjeta) y lanza el tour si 'unseen'. Happy path F11 (createLocal→adoptVault→openNote('Bienvenida.md')) intacto. ✅
2. **Secuencia tour-primero** — BackupCard gated en `!tour.active`; el tour corre primero, la tarjeta no se encima. ✅
3. **Ancla del tour** — `data-tour="respaldo"` en el BackupButton SIEMPRE montado; el paso 3 del tour siempre encuentra su ancla. ✅
4. **STAT-01 honesto por-bóveda** — "Todo en la nube" solo con `connected && remote-propio && pushCount===0`; `remote` se re-deriva del origin de la bóveda activa (post CR-01/CR-02). ✅
5. **Respaldo idempotente + auto-sufijo** — `vaultEnableBackup` salta createRepo si la bóveda ya tiene origin; en colisión 422 reintenta con sufijo (cap 20); nunca reusa el repo de otra bóveda (seguridad CR-01). ✅
6. **Persistencia round-trip** — tour.state y backup.onboarding vía IPC `geode:*` con coerción de enum en el main. ✅

## E2E Flow (1/1 complete)

Usuario nuevo → bienvenida sin jerga → "Crear mi primer cuaderno" (1 click, local, Bienvenida.md sembrada) → tour escribir→guardar→respaldar→historial sobre botones reales → tarjeta de respaldo → conectar (o hand-off a signup) → repo privado + primer push automático → guardados posteriores se respaldan solos con "Todo en la nube" honesto. **Sin eslabón roto.**
